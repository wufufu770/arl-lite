# 性能基线

规模档:**medium** · Python 3.12.3 · Linux x86_64

数据量:36000 行(domains=1000, hosts=10000, ports=10000, findings=10000, sites=5000)

## 分阶段耗时

| 阶段 | 行数 | 耗时(s) | 吞吐(行/s) | 峰值内存(kB) | 备注 |
|---|---:|---:|---:|---:|---|
| `write:findings` | 10,000 | 2.057 | 4,862 | 30 |  |
| `run_all_rules` | 36,000 | 1.491 | 24,151 | 4,517 | 37 条规则 / 2001 个命中 |
| `write:ports` | 10,000 | 1.428 | 7,003 | 39 |  |
| `write:hosts` | 10,000 | 1.230 | 8,127 | 38 |  |

| `write:domains` | 1,000 | 0.153 | 6,530 | 38 |  |
| `confidence.assess` | 2,001 | 0.029 | 68,676 | 625 | 逐条评估 2001 个命中 |
| `risk_score.compute_asset_risks` | 2,001 | 0.001 | 3,445,616 | 5 | 从 2001 个命中聚合 |
| **合计** | **36,000** | **7.590** | **4,743** | **4,517** | |

## 结论

- **36,000 行全流水线 7.59s**(不含网络)
- **37 条规则**跑完 36,000 行,命中 2001 个
- 写入与规则引擎的耗时占比见上表 —— **写入占比高就该先查索引,规则占比高就该先看规则复杂度**
- 峰值内存 4.4 MB(下界,见下方说明)

## 局限

- tracemalloc 只跟踪 Python 对象分配,**不含** SQLite 页缓存与 解释器自身开销,所以峰值内存是**下界**,不是进程真实 RSS
- 本基线**不含网络**。子域名枚举与 HTTP 探测的耗时由 crt.sh / 目标站决定,与本项目代码无关,且 crt.sh 实测限流严重(429/502),拿它当基准不可复现
- 耗时取 3 次的中位数(单次会被 GC 和磁盘缓存干扰)

# 性能基线:三档趋势

| 规模 | 总行数 | 合计(s) | 吞吐(行/s) | 规则引擎(s) | 峰值(MB) |
|---|---:|---:|---:|---:|---:|
| small | 7,200 | 2.17 | 3,317 | 0.91 | 1.5 |
| medium | 36,000 | 7.59 | 4,743 | 1.49 | 4.4 |
| large | 180,000 | 40.51 | 4,444 | 7.78 | 4.4 |

## 线性度

相邻档数据量约 x5。耗时涨得比 5 倍多,就要怀疑有全表扫或 N+1。

| 区间 | 数据 | 合计耗时 | 判定 |
|---|---:|---:|---|
| small → medium | x5.0 | x3.50 | 次线性(0.70x 预期,固定开销被摊薄) |
| medium → large | x5.0 | x5.34 | 线性 ✓ |
